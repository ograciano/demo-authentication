Título: Flujo obligatorio de logout y revocación de sesión

Objetivo funcional:
Permitir que un usuario cierre sesión invalidando el refresh token asociado para impedir futuras renovaciones JWT.

---

# Flujo funcional requerido

## Logout

Endpoint obligatorio:

POST /api/auth/logout

## Request

{
  "refreshToken": "jwt-refresh-token"
}

## Respuesta exitosa

200 OK

{
  "status": "LOGOUT_SUCCESS"
}

---

# Comportamiento obligatorio

Después de logout:

- el refresh token NO debe poder reutilizarse
- el endpoint /api/auth/refresh debe devolver 401
- la sesión debe considerarse terminada

---

# Validaciones obligatorias

El sistema debe validar:

1. Refresh token firmado.
2. Refresh token válido.
3. Usuario existente.
4. Estado del usuario.
5. Token no revocado previamente.

---

# Estrategia mínima esperada

La implementación debe dejar preparado un mecanismo de revocación.

Opciones válidas:

- blacklist en memoria
- persistencia temporal
- repositorio de tokens revocados
- estrategia extensible futura

---

# Casos inválidos

## Refresh token inválido

Debe responder 401 Unauthorized.

## Refresh token revocado

Debe responder 401 Unauthorized.

## Payload inválido

Debe responder 400 Bad Request.

---

# Reglas de seguridad

- Nunca loggear refresh token completo.
- No exponer secretos.
- No exponer detalles internos JWT.
- Mantener errores homogéneos.
- Mantener contratos REST consistentes.

---

# Cambios técnicos obligatorios

## AuthController

Debe implementar:

POST /api/auth/logout

## AuthService

Debe implementar:

- lógica de revocación
- invalidación de sesión
- validación de token revocado

## Refresh flow

Debe rechazar tokens revocados.

---

# Testing obligatorio

Validar:

- logout exitoso
- logout con token inválido
- refresh posterior a logout retorna 401
- protección ante reutilización de refresh token

---

# Resultado esperado final

- logout funcional
- refresh token inutilizable tras logout
- OpenAPI actualizado
- pruebas pasando
- comportamiento consistente con seguridad JWT
